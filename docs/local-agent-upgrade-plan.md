# Kế hoạch cập nhật local agent an toàn

## Mục tiêu và quyết định

Local host (`kind=local` hoặc `managedBy=system`) phải thấy phiên bản agent đang chạy, bản phát hành tương thích mới nhất, độ mới của heartbeat, và cách cập nhật. Quản trị viên có thể xác nhận một job cập nhật từ dashboard; job chỉ thành công sau khi agent mới gửi heartbeat. Nếu nâng cấp thất bại, updater khôi phục binary cũ và báo kết quả kiểm chứng rollback. Không chạy shell tùy ý, không mount Docker socket/systemd vào API, không truyền URL/path/binary từ browser, không tự động cập nhật mặc định. Giữ nguyên đường SSH upgrade cho remote agent.

**Kiến trúc đã chọn:** API lưu job và phát hành manifest được xác thực; host chạy updater systemd riêng, pull job qua API bằng credential riêng bị giới hạn đúng `vps_local_host`. Updater được cấp quyền chỉ cho staging, thay binary `/usr/local/bin/vps-manager-agent` và restart đúng unit `vps-manager-agent.service`. Không dùng agent đang được nâng cấp để tự thay nó. API container không có quyền host root. Bản đầu tiên vẫn cung cấp hướng dẫn nâng cấp thủ công khi chưa cài updater; không hiển thị nút hành động có vẻ hoạt động khi updater vắng mặt.

## Hiện trạng cần sửa

- `packages/web/src/components/dashboard/servers/ServerCard.tsx` và `ServerTable.tsx` loại local khỏi `canUpgrade`; `DashboardContext.tsx` gọi `upgradeAgent()` hiện dành cho remote.
- `packages/api/src/agents/agent-upgrader.service.ts` có staging/checksum, rollback và kiểm tra heartbeat qua SSH; không tái sử dụng SSH trên local. `VpsService` chặn lifecycle remote trên system-managed host. `AgentLifecycleCoordinator` chỉ giữ lock trong memory, không đủ làm khóa job bền vững qua restart/multi-instance.
- `AgentState.version`, `lastSeenAt` được lưu từ ingest; system info/metric cũng có `agentVersion`. Không có catalog release. `Dockerfile` build Go không truyền `-ldflags` nên binary đóng trong API image trả `dev`; `scripts/agent/build-agent.mjs` mới truyền phiên bản. CI chỉ push image theo SHA, không phát hành artifact/manifest agent độc lập. `scripts/install/install-local-agent.sh` cài binary systemd, không có updater.
- Một container API/web được deploy không chứng minh systemd agent đã đổi. Phải phân biệt version binary đang cài, version process thực sự gửi heartbeat, và desired release; chỉ heartbeat tươi mới xác nhận nâng cấp.

## Hợp đồng phát hành và tin cậy

1. CI build artifact Linux/amd64 (chỉ thêm kiến trúc khác khi có build/test tương ứng) một lần cho release, inject build ID bất biến (commit SHA hoặc release ID) vào `internal/version.Value` ở cả build standalone và Dockerfile. Giữ `-version` để đối chiếu. Không dùng `dev`, `latest`, timestamp hoặc semver thuần làm định danh duy nhất. Sửa nguồn version hardcode `1.0.0` trong `AgentInstallerService` bằng version thực từ binary/heartbeat.
2. Manifest canonical, ví dụ `{releaseId, version, buildId, channel, publishedAt, apiCompatibility:{min,max}, artifacts:[{os,arch,size,sha256,url}], signature}`. Chữ ký Ed25519 trên bytes canonical/immutable; public key ghim ở updater và API, private key chỉ ở CI protected release environment. HTTPS + allowlist host cố định, giới hạn dung lượng, timeout và checksum SHA-256 là lớp bổ sung, không thay chữ ký. Chặn rollback xuống release cũ trừ một job rollback nội bộ đã ghi nhận.
3. CI xuất artifact và manifest bất biến, kiểm tra binary `-version`/build ID, xác minh chữ ký và hash trước khi công bố release; cập nhật con trỏ kênh `stable` theo thao tác phát hành có kiểm soát. API cache manifest đã xác minh, hiển thị `release unavailable` khi hết hạn/lỗi thay vì tự đoán từ image tag. Chỉ nhận release tương thích API/schema và đúng OS/arch. Lưu release ID/hash của job tại lúc xác nhận để con trỏ stable đổi không làm job đổi mục tiêu.
4. Giai đoạn bootstrap updater được cài thủ công bằng gói có chữ ký và hướng dẫn riêng. Rotation của release signing key cần giai đoạn overlap, revocation và runbook; không lấy public key từ cùng manifest chưa được tin cậy.

## Hợp đồng API và trạng thái

- `GET /api/vps/:id/agent-update`: trả `{installed:{version,buildId,lastSeenAt,fresh},available:{releaseId,version,buildId,publishedAt}|null, compatibility, updater:{installed,healthy}, state}`. State phân biệt `unknown` (heartbeat cũ/không có build ID), `current`, `available`, `incompatible`, `release_unavailable`, `updater_unavailable`; không hiển thị `current` khi heartbeat cũ. API không tin binary version do browser gửi.
- `POST /api/vps/:id/local-agent-upgrades` với `{releaseId,confirmationToken}` (hoặc cơ chế xác nhận mutation hiện có); admin session/CSRF/rate limit/audit bắt buộc. Chỉ local host, release được ký và tương thích, updater có heartbeat mới, không có job active; tạo job bền vững có idempotency key, target release/hash, deadline và actor. `GET /api/vps/:id/local-agent-upgrades/:jobId` trả trạng thái lỗi đã lọc. Không nhận URL, command, path, token agent, hay binary từ UI.
- Updater dùng credential riêng scope local-updater (không dùng credential metrics/SSH): claim atomically với lease/fencing token, report progress và outcome idempotent; TLS, rotate/revoke credential, bound identity tới local VPS. Chỉ một job active qua unique DB constraint/CAS; lease hết hạn không tự replay thao tác sau điểm swap. Sau restart API/updater, reconcile trạng thái từ journal host và heartbeat trước khi quyết định tiếp tục/rollback.
- Trạng thái job: `queued → claimed → downloading → verifying → staging → restarting → awaiting_heartbeat → succeeded`; nhánh lỗi `rolling_back → rolled_back` hoặc `rollback_unverified` (cần can thiệp thủ công). Deadline ở mỗi pha, không bao giờ báo thành công dựa trên systemd active đơn thuần. Audit start/success/failure với release ID, không ghi secrets hoặc stdout tùy ý. Kết quả phải còn xem được sau reload/multi-instance.
- `lastSeenAt`/version ingest cần so sánh với baseline ngay trước restart và build ID đích; stale host metric không được giả làm heartbeat mới. Heartbeat phải từ đúng VPS credential/agent instance. Khi rollback, xác nhận heartbeat build ID cũ mới gắn `rolled_back`; nếu không có, giữ `rollback_unverified`.

## Updater host và quyền hạn

1. Tạo host updater service/timer hoặc daemon pull-only, chạy bằng user riêng; chỉ polling authenticated API qua outbound HTTPS. Không mở privileged socket TCP/public. Root action là helper cố định với argv đã kiểm tra, chạy qua một unit/template có policy cố định; không nhận shell text. Chỉ được thay đúng binary agent và restart đúng unit; không đọc config/token agent hoặc runtime Docker state. Dùng filesystem staging cùng mount với binary để rename nguyên tử; cấm symlink/path traversal và xác minh owner/mode.
2. Claim và ghi journal fsync gồm job ID, release/hash, pha, binary cũ/new, baseline heartbeat; khóa filesystem toàn cục và một job DB. Tải artifact vào file tạm giới hạn kích thước, verify manifest signature, checksum, `-version`/build ID, executable/arch; không thay binary nếu bất kỳ kiểm tra nào lỗi.
3. Stage backup binary cũ, atomic rename binary mới, restart unit với timeout. Giữ state/config/credential Docker nguyên vẹn. Poll server heartbeat mới đúng build ID trước khi xóa backup. Nếu service thất bại hoặc timeout, restore backup nguyên tử, restart và xác minh heartbeat cũ; nếu chưa xác minh thì giữ backup/journal, báo tình trạng khẩn cấp, không tiếp tục job khác.
4. Sau crash/reboot, updater đọc journal và xác minh file hash/service/heartbeat để tiếp tục đợi hoặc rollback; **không swap/restart lại một mutation không rõ kết quả**. Bảo vệ disk full, download cắt ngang, mất mạng, signature sai, report API thất bại, và restart API. Retain bounded logs không chứa payload/config/token; systemd hardening (`NoNewPrivileges` phần không cần root, `ProtectSystem`, `ReadWritePaths` tối thiểu, capability và network policy phù hợp).
5. `scripts/install/install-local-agent.sh`/`scripts/install/install.sh`: bootstrap updater một lần, không thay cấu hình local agent đang chạy khi chỉ nâng cấp binary; hỗ trợ phát hiện updater cũ/thiếu, uninstall an toàn và runbook khôi phục ngoại tuyến. CI deploy API/web **không** tự âm thầm nâng cấp agent; manifest được publish là điều kiện tạo notification.

## UX dashboard

- Ở cả card và table, local host có badge phiên bản process + build ID, `lastSeenAt`, trạng thái update (không lấy `Local` thay cho online/offline). Thêm chi tiết trong workspace agent/Settings; thông báo có bản mới xuất hiện khi release compatible và heartbeat đủ mới. Khi offline/unknown hiện lý do, không khẳng định agent mới nhất.
- Nếu updater chưa cài: nút `Xem hướng dẫn cập nhật` và lệnh thủ công theo release ID/checksum, không hiện nút upgrade khả dụng. Nếu updater sẵn sàng: `Cập nhật agent` mở `AlertDialog` ghi current → target, downtime, release ID, xác nhận admin. Disabled state có lý do cụ thể (job đang chạy, incompatible, stale, unsupported architecture).
- Job progress từ persisted state qua SSE hiện có + fetch/poll fallback, a11y `aria-live`, progressbar chỉ có % khi tiến độ thực; tải lại trang không làm mất trạng thái. Kết quả thành công hiển thị heartbeat/build mới; rollback và rollback_unverified hiển thị cảnh báo cùng hướng dẫn vận hành. Dùng `AgentLifecycleStatus` và action patterns đang có, nhưng tách nhánh local khỏi SSH remote; không nhân đôi logic hành động ở card/table.

## Thứ tự thực hiện và điều kiện nghiệm thu

1. **Release identity/catalog:** chỉnh `Dockerfile`, `scripts/agent/build-agent.mjs`, `internal/version`, CI publish; manifest chữ ký/hash, API read-only release endpoint. Chứng minh binary image và standalone cùng build ID; manifest bị sửa/signature sai bị từ chối; version `dev` không được quảng bá là current.
2. **Quan sát + manual fallback:** expose heartbeat version/build/freshness và release comparison; web card/table/workspace hiển thị nhất quán, link hướng dẫn thủ công. Smoke với heartbeat mới/cũ, release không có, local vs remote; không yêu cầu updater để xem trạng thái.
3. **Updater + bootstrap:** cài host helper/service qua script, credential riêng, khóa/journal, verify/swap/rollback; integration test trong Linux VM/container có systemd hoặc harness unit giả với filesystem thật, bao gồm crash sau swap, signature sai, disk full và offline. Không thử nâng cấp production trước khi qua fault injection.
4. **API job bền vững:** migration JSON/PostgreSQL theo repository convention, claim lease/fencing, authorization, audit, idempotency, timeout/reconcile; test race hai yêu cầu và multi-instance/restart, replay result, expired lease, CSRF/privilege denial. Không tái dùng in-memory coordinator làm nguồn chân lý.
5. **UX actionable:** bật nút local khi updater healthy, dialog confirm, tiến độ persisted, rollback/failure; giữ remote upgrade không đổi. Browser smoke card + table, keyboard/focus, reload trong job, offline updater, success/failure.
6. **Release gate và rollout:** cài updater thủ công trên staging, ký/publish release, tạo một job, kiểm tra binary `-version`, `systemctl`, heartbeat build ID tăng sau baseline, Docker ingest `source_sequence` tăng và chart có ít nhất hai mẫu mới. Thử rollback có kiểm soát; sau đó production canary. Tài liệu nâng cấp/khôi phục, key rotation và changelog; không xóa backup khi rollback chưa xác minh.

**Định nghĩa hoàn thành:** local host báo chính xác có/không có update; khi updater sẵn sàng admin thực hiện nâng cấp hoàn toàn trong dashboard, job sống qua reload/restart, chỉ thành công sau heartbeat build mới; lỗi được rollback và xác minh hoặc báo rõ cần can thiệp; API container không có quyền host root/socket; remote flow và monitoring không hồi quy.

## Cập nhật kiến trúc: Bundled Binary & Protocol v2

Hệ thống đã chuyển từ catalog ký số ngoài (Ed25519 signing key) sang **kiến trúc bundled binary trực tiếp từ API image**:
1. **Nguồn binary đóng gói:** Binary Linux amd64/arm64 được đóng gói sẵn trong API container tại `/app/agent/vps-agent-linux-amd64` (hoặc cấu hình qua `AGENT_BINARY_PATH`). API khởi động qua `BundledAgentService` để đọc header ELF64, kiểm tra định dạng little-endian, kiến trúc máy, tính SHA-256, kích thước và đọc 40-hex commit build ID từ nhãn VCS.
2. **Loại bỏ khóa ký thủ công cho local update:** Nâng cấp local agent không còn phụ thuộc biến môi trường `AGENT_RELEASE_SIGNING_KEY`, `AGENT_RELEASE_PUBLIC_KEY`, hay `AGENT_RELEASE_MANIFEST_URL`. Artifact được phục vụ trực tiếp qua HTTPS scoped endpoint `GET /api/local-updater/jobs/:jobId/artifact`.
3. **Yêu cầu Updater Protocol v2:** Daemon updater gửi header `X-Updater-Protocol-Version: 2` cho mọi yêu cầu (claim, progress, download, result). API từ chối client protocol 1 với mã `409 updater_incompatible`.
4. **Migration updater hiện hữu:** Host updater cũ được nâng cấp lên protocol 2 qua lệnh `install-updater.sh --upgrade --binary <path> --config /etc/vps-updater/config.json`, giữ nguyên cấu hình, token scoped credential, thư mục `/var/lib/vps-updater` và nhật ký journal. Cấu hình updater không còn bắt buộc `pinnedPublicKey`.
5. **Bảo toàn nguyên tắc an toàn:** Quá trình swap binary qua helper root với xác minh SHA-256 ghim chặt từ job, backup binary cũ, atomic rename, kiểm tra heartbeat tươi mang đúng commit build ID trước khi báo thành công, và cơ chế rollback tự động khi lỗi restart hoặc hết hạn deadline vẫn được giữ nguyên vẹn. API container tuyệt đối không có quyền root host hay socket Docker/systemd.
